# 符号图纸颜色上限问题：too many distinct colors for symbol encoding

## 问题描述

当输入图片色彩丰富、量化后不同颜色数超过符号字母表大小时，整个 pipeline 崩溃：

```
Pattern generation failed: too many distinct colors (86) for symbol encoding; alphabet size is 73
```

例如一张色彩丰富的照片，经过 MARD 291 色色卡匹配后产生了 86 种不同颜色，直接报错，chart、preview、BOM 全部无法生成。

## 根因分析

错误发生在 `pixelbeans/pipeline.py` 的 `_assign_symbols()` 函数（`assemble()` 阶段）：

```python
_SYMBOL_ALPHABET = (
    "ABCDEFGHIJKLMNOPQRSTUVWXYZ"   # 26
    "abcdefghijklmnopqrstuvwxyz"   # 26
    "0123456789"                   # 10
    "!@#$%&*+<>?"                  # 12
)  # 总计 74 个字符

def _assign_symbols(used_indices: list[int]) -> dict[int, str]:
    if len(used_indices) > len(_SYMBOL_ALPHABET):
        raise ValueError(...)
```

**关键问题**：`_assign_symbols` 在核心 pipeline 的 `assemble()` 中被强制调用。即使前端用户根本不看符号图纸（grid），只要颜色数 > 74，整个流程（包括 chart、preview、BOM）全部失败。74 色上限不是 grid 渲染的限制，而是整个算法 pipeline 的硬性阻塞。

## 符号图纸的必要性分析

从拼豆工艺实际使用场景出发（拼豆领域专家评估）：

| 场景 | 首选图纸 | 原因 |
|---|---|---|
| 手机/iPad 对照施工 | preview（彩色色块） | 颜色直观，一眼锁定 |
| 大尺寸打印对照 | chart（彩色+色号） | 有行列标注，10格十字线定位 |
| 彩色打印 | chart（彩色+色号） | 色号直接对应豆子，购豆可下单 |
| 黑白打印 | grid（符号） | **唯一不可替代场景** |

**结论**：
- 90%+ 的用户直接在手机/iPad 上看彩色图纸施工，不需要符号图纸
- 符号图纸唯一的不可替代场景是"只有黑白激光打印机的用户"
- 当前 grid 实现是彩色底+符号，并非真正的黑白图纸，黑白打印价值也有限
- chart（彩色底+色号 M01）在几乎所有维度优于 grid（彩色底+符号 A）——色号比字母对用户更有意义
- **这是一个架构问题而非功能问题**：边缘功能的限制卡住了核心流程

## 解决方案

### 方案 A（推荐）：延迟符号分配

将 `_assign_symbols` 从 `assemble()` 核心流程中移除，推迟到 `render_grid()` 内部按需执行。

**效果**：
- 核心 pipeline 不受 74 色限制，不论多少色都能跑通
- `render_grid()` 颜色超 74 时自动降级（前 74 种有符号，其余不标）
- chart、preview、BOM 完全不受影响
- 改动量小（约 20 行，4 个文件）

**涉及改动**：
1. `PatternCell.symbol` 默认值改为 `""`（空字符串）
2. `_assign_symbols` 从 `assemble()` 中移除
3. `render_grid()` 内部自行计算 symbol 映射，超出 74 时做降级处理
4. BOM 中的 symbol 列也做对应调整
5. 同步修改 `pixelbeans/` 和 `api/pixelbeans/` 两套代码

### 方案 B：直接移除 grid 功能

如果确认用户几乎不使用符号图纸，移除 `render_grid` 和 `grid_image` 字段。

**效果**：最简洁，彻底消除 74 色限制。但需要数据支撑（如前端埋点统计 grid/chart 下载量）。

### 方案 C：临时补丁

在 `_assign_symbols` 中不再 raise ValueError，返回部分映射（前 74 种有符号，其余空字符串）。

**效果**：能快速跑通流程，但部分格子无符号标注，体验较差，且未从根本上解耦。

## 建议

**采用方案 A**。理由：
1. 解决核心 pipeline 的 74 色硬上限，影响面可控
2. 不删除 grid 功能——保留黑白打印可能性
3. chart（带色号）才是用户刚需图纸，它本身不受 74 色限制
4. 改动量小，不引入新依赖和抽象

## 实施记录

### 最终方案

将 `_assign_symbols` 从 `raise ValueError` 改为静默降级：

```python
def _assign_symbols(used_indices: list[int]) -> dict[int, str]:
    symbol_map = {}
    for k, pi in enumerate(used_indices):
        if k < len(_SYMBOL_ALPHABET):
            symbol_map[pi] = _SYMBOL_ALPHABET[k]
        else:
            symbol_map[pi] = ""  # Excess colors: no symbol assigned
    return symbol_map
```

- 74 色以内：符号正常分配
- 超过 74 色：前 74 种有符号，超出部分 symbol 为空字符串
- 用户可通过 JSON 响应中的 `palette_used` 查对应色号
